# 实验迭代机制

> 目标：把实验从「一次性验证」变成「低风险迭代机制」。重点关注小流量、灰度、扩量、全量、反转、打包验证等真实业务流程。

## 1. 实验迭代不是一次 AB，而是一条发布链路

一个策略/功能从 idea 到全量，建议经历：

```text
离线验证
  → A/A 或空转检查
  → 小流量 AB
  → 灰度扩量
  → 稳定性观察
  → 全量发布
  → 小流量反转 / holdout 长期观察
  → 复盘沉淀
```

不是所有实验都必须走完整链路，但高风险、核心链路、算法策略、长期收益不确定的实验，应该尽量走完整链路。

## 2. 实验状态机

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| 草稿 | 实验方案未评审 | 评审通过 / 驳回 |
| 待上线 | 配置完成，等待发布窗口 | 上线 / 取消 |
| A/A 空转 | 分流已开，但各组策略一致 | 分桶和指标无异常 |
| 小流量实验 | 低比例真实流量进入 | 无护栏异常且样本够，进入扩量 |
| 灰度扩量 | 逐步提高实验流量 | 效果稳定，进入全量；异常则回滚 |
| 数据回收 | 实验停止进入新流量，但等待转化窗口结束 | 指标窗口完整 |
| 分析决策 | 指标计算完成 | 上线 / 回滚 / 继续实验 / 重做 |
| 全量发布 | 实验策略成为默认策略 | 进入反转或长期监控 |
| 反转观察 | 从原对照组抽小流量继续做对照 | 长期指标稳定后结束 |
| 归档复盘 | 决策完成 | 形成案例库和方法论 |

## 3. 小流量实验怎么用

小流量不是为了直接证明最终收益，而是为了降低风险、发现明显问题。

适合小流量先行的情况：

- 新功能可能影响核心路径；
- 推荐/搜索/广告模型改动；
- 交易、支付、履约等强业务风险链路；
- 埋点或指标链路还未完全稳定；
- 预期收益大，但风险也大。

小流量阶段重点看：

- 错误率、崩溃率、延迟、投诉、退款等护栏指标；
- 曝光、点击、转化链路是否完整；
- 分流比例是否符合预期；
- 是否出现明显负向。

不要在样本量不足的小流量阶段过度解读 p-value。

## 4. 灰度扩量规范

推荐扩量节奏：

| 阶段 | 流量比例 | 判断重点 |
|---|---|---|
| 0.5% - 1% | 冒烟验证 | 工程稳定性、日志、埋点、配置是否正确 |
| 5% | 小流量风险验证 | 护栏指标、SRM、核心链路是否异常 |
| 10% - 20% | 初步效果验证 | 核心指标方向、分层表现、负反馈 |
| 50% | 大流量验证 | 指标显著性、稳定性、资源成本 |
| 100% | 全量 | 上线后长期监控、反转/holdout |

每次扩量前必须检查：

- 上一阶段是否跑满最低观察窗口；
- 护栏指标是否无显著负向；
- 核心指标是否方向一致；
- 数据质量是否通过；
- 是否有业务活动、节假日、版本发布干扰。

## 5. 反转实验

反转实验用于验证：短期 AB 正向后，全量上线是否仍然有长期收益，是否存在短期新奇效应或长期负面影响。

典型做法：

```text
原实验：A=旧策略，B=新策略，B 胜出
全量：新策略成为默认策略
反转：从原 A 组或保留流量中抽小部分用户继续使用旧策略
对比：新默认策略 vs 旧策略小流量对照
```

适用场景：

- 算法模型改版；
- 推荐/搜索排序策略；
- 影响用户长期习惯的产品功能；
- 短期指标容易正向、长期指标不确定的策略；
- 大盘收益需要长期确认的实验。

不建议反转：

- 原实验已经显著负向；
- 新策略涉及强合规、安全修复，不能让用户继续用旧策略；
- 原策略不可再现或工程上已删除；
- 对照用户体验损伤过大。

## 6. 打包验证

很多业务策略单独实验时收益很小，或者多个策略之间有交互，单个实验不能回答「整体策略包是否提升大盘」。这时可以做打包验证。

适用场景：

- 搜索/推荐多策略连续迭代；
- 多个小优化单点收益弱，但希望验证整体收益；
- 多个策略之间存在协同或相互抵消；
- 已有多个小实验通过，需要验证全量组合效果。

做法：

```text
Base：线上旧策略包
Package：多个待上线策略组成的新策略包
在贯穿层/holdout 层做长期 AB
观察大盘核心指标、护栏指标、长期留存/转化
```

注意：

- 打包验证能回答「整体是否有效」，不能精确拆分每个策略贡献；
- 如果打包正向，后续要记录包内策略清单；
- 如果打包负向，需要拆包回溯，找到拖累策略。

## 7. 实验决策规则

| 结果 | 建议动作 |
|---|---|
| 核心指标显著正向，护栏无负向 | 扩量 / 全量 / 进入反转观察 |
| 核心指标正向但不显著 | 延长周期、扩大样本、检查方差、看业务价值 |
| 核心指标持平，护栏无异常 | 如果成本低可放弃；如果战略重要可重构实验 |
| 核心指标负向或护栏负向 | 暂停 / 回滚 / 定位原因 |
| SRM 或数据质量异常 | 不做上线决策，先修数据和分流问题 |
| 分层结果冲突 | 检查是否辛普森悖论、样本偏差、异质性效果 |

## 8. 平台要支持的能力

- 实验状态机：草稿、待上线、运行中、暂停、数据回收、报告完成、归档；
- 动态调流：支持扩量、缩量、暂停；
- 灰度配置：支持按人群、端、版本、地域、白名单发布；
- 一键回滚：配置回退到 control/default；
- 反转实验：从原对照组或保留桶继续抽样；
- 父子实验：支持 holdout、黑白盒、打包验证；
- 决策记录：上线/回滚/继续实验必须留痕；
- 实验复盘：成功、失败、异常都进入案例库。

# 01_实验可行性分析

实验可行性分析是实验设计的第一关。它不急着算样本量、配流量、写指标，而是先判断：**这个业务问题是否值得实验、能不能随机实验、如果不能随机实验应该用什么替代方案**。

一句话：实验可行性分析回答的是 **“这件事要不要做实验，以及适合用哪种方式验证”**。

## 1. 本模块要解决什么问题

| 判断层 | 核心问题 | 如果判断不清会怎样 |
|---|---|---|
| 值不值得做 | 业务问题是否足够重要？预期收益是否覆盖实验成本和风险？ | 为小问题消耗流量和研发资源 |
| 能不能做 | 是否能随机分组？实验单元是否稳定？样本是否足够？ | 实验组和对照组不可比，结论不可信 |
| 该不该做 | 是否有伦理、合规、体验、品牌或核心链路风险？ | 指标正向但带来用户体验或业务风险 |
| 怎么替代 | 如果不能做标准 AB，是否有其他评估方式？ | 把所有问题都硬塞进 AB Test |

可行性分析的最终产出不是一份完整实验方案，而是一个明确结论：

- **可做标准随机对照实验**：进入 [02_实验方案设计](02_实验方案设计.md)。
- **有条件可做**：需要先补齐埋点、流量、人群、工程隔离或风控机制。
- **不适合做标准 AB**：转向 interleaving、准实验、灰度观察、离线评估或问卷研究。
- **暂不建议实验**：收益不足、风险过高、问题定义不清，先回到业务问题澄清。

## 2. 实验可行性分析框架

| 分析项 | 需要回答的问题 | 判断标准 | 主要产出 |
|---|---|---|---|
| 实验背景 | 当前业务问题是什么？为什么现在要验证？ | 问题具体、场景清楚、owner 明确 | 背景说明、问题定义 |
| 预期收益 | 成功后提升什么？提升多少算值得？ | 有明确收益指标或战略价值 | 预期收益、优先级 |
| 风险成本 | 会伤害哪些用户体验或业务指标？研发和流量成本多大？ | 风险可控，有止损机制 | 风险边界、止损条件 |
| 随机化可行性 | 是否能随机分组？分组后体验是否稳定？ | 实验单元可识别、可稳定分桶 | 是否可做 RCT |
| 样本与流量 | 有多少目标人群？实验周期内能否积累足够样本？ | 样本量基本够，周期可接受 | 初步样本/周期判断 |
| 干扰与污染 | 用户之间、实验之间是否互相影响？ | 干扰可隔离或可建模 | 隔离、互斥、分层建议 |
| 数据可观测性 | 曝光、行为、转化、护栏指标是否能被记录？ | 数据链路完整，口径可定义 | 埋点和指标准备清单 |
| 替代评估 | 如果不能随机，是否有其他因果或评估方法？ | 能找到可信反事实或对照方式 | 替代方案 |

## 3. 第一步：把业务问题转成可验证问题

很多实验不可行，不是统计问题，而是业务问题没有定义清楚。

### 3.1 不好的问题

- “这个新功能效果好不好？”
- “这个模型要不要上线？”
- “这个活动有没有用？”
- “用户喜不喜欢新版？”

这些问题太泛，无法直接实验。

### 3.2 更好的问题

| 原始问题 | 可验证版本 |
|---|---|
| 新功能效果好不好？ | 新功能是否能让目标用户的下单转化率提升至少 1%，且不提高投诉率？ |
| 模型要不要上线？ | 新排序模型是否能提升搜索结果点击满意度，同时不降低支付转化？ |
| 活动有没有用？ | 补贴活动是否能提升新客首单率，且补贴 ROI 大于 1？ |
| 用户喜不喜欢新版？ | 新版是否提升核心任务完成率，并降低退出率？ |

可验证问题通常包括：

```text
在什么人群 / 场景下，
对什么策略 / 功能 / 模型做改变，
预期影响哪个核心指标，
最小可接受收益是多少，
哪些风险指标不能变坏。
```

## 4. 第二步：判断是否适合随机对照实验

标准 AB 实验的前提是：实验组和对照组除了处理不同，其他条件尽量随机一致。

### 4.1 随机实验可行的典型条件

| 条件 | 说明 |
|---|---|
| 有明确实验单元 | 能按用户、设备、商家、门店、订单、内容等稳定分组 |
| 实验处理可控 | 能控制谁看到新策略，谁看到旧策略 |
| 实验单元相对独立 | 一个单元的处理不会显著影响另一个单元 |
| 数据可观测 | 曝光、行为、转化和护栏指标能被记录 |
| 样本足够 | 目标人群和流量能支撑检测预期效果 |
| 风险可控 | 有小流量、回滚、止损和监控机制 |

### 4.2 不适合直接 AB 的情况

| 不适合原因   | 典型表现                    | 建议处理                    |
| ------- | ----------------------- | ----------------------- |
| 无法随机    | 政策按城市上线、功能按版本自然发布       | 准实验、DID、断点回归、匹配方法       |
| 强网络效应   | 用户之间会互相影响，如社交、供需撮合、内容生态 | 聚类随机、城市/社区级随机、准实验       |
| 低频长周期   | 转化很少或效果要几周/月才出现         | 拉长周期、扩大人群、找前置指标、做离线或准实验 |
| 改动极小    | 排序微调、搜索结果局部变化，AB 不敏感    | interleaving 或更敏感指标     |
| 高风险不可回滚 | 支付、安全、合规修复、重大体验风险       | 先离线验证、小流量灰度、风控白名单       |
| 对照不伦理   | 明知旧策略有明显损害，不能继续给对照组     | 灰度观察、前后对比、保守上线监控        |
| 指标不可观测  | 关键行为无埋点、链路 join 不上      | 先补数据链路，不直接实验            |

## 5. 第三步：选择实验或评估方式

整合 [实验方式](实验方式.md)、[ab-test](ab-test.md)、[interleaving介绍](interleaving介绍.md) 中的内容，可以先按下面的决策表选择方法。

| 场景 | 推荐方法 | 为什么 |
|---|---|---|
| 常规产品功能、文案、按钮、流程改动 | AB Test / 完全随机设计 | 改动可控，用户可随机分组，指标直观 |
| 搜索/推荐排序的微小改动 | Interleaving | 同一次请求中比较两个排序结果，敏感度更高，所需流量更少 |
| 需要控制人群差异 | 随机区组 / 分层随机 | 先按地域、端、活跃度等分层，再在层内随机 |
| 同一对象可以接受多个处理 | 配对设计 / 交叉设计 | 利用自身对照，减少个体差异 |
| 多个因素同时变化 | 析因设计 / 正交设计 | 识别主效应和交互效应，降低组合实验成本 |
| 无法随机上线 | 准实验 / 因果推断 | 通过非随机数据构造反事实 |
| 想理解态度、满意度、认知 | 问卷 / 访谈 | 适合回答主观感受，但要关注信度、效度 |
| 先验证工程链路 | A/A 或空转 | 不改变用户体验，先验证分流和指标链路 |

## 6. 第四步：初步判断样本与流量是否够

可行性阶段不一定要精确计算样本量，但至少要做初筛：

| 检查项 | 说明 |
|---|---|
| 目标人群规模 | 实验条件过滤后，每天还有多少可用用户 / 请求 / 商家 / 订单？ |
| 基线指标水平 | 当前转化率、留存率、点击率、GMV、人均收入等是多少？ |
| 预期提升幅度 | 希望检出的最小效果是多少？例如转化率提升 0.5pp 或相对提升 2% |
| 可接受周期 | 业务能等几天、几周还是几个月？ |
| 指标波动 | 指标天然波动大不大？是否长尾？是否需要方差缩减？ |
| 流量占用 | 实验需要占多少流量？是否会挤占其他实验？ |

如果样本明显不足，常见处理方式：

- 增加实验周期；
- 扩大目标人群；
- 提高实验流量；
- 换更敏感的前置指标；
- 做 CUPED、分层、metric transformation 等方差缩减；
- 改用 interleaving 或离线评估；
- 接受只能观察方向，不能做强统计结论。

## 7. 第五步：判断风险与止损条件

实验不是只追求收益，也要提前明确什么情况下必须停。

| 风险类型 | 例子 | 可行性阶段要确认什么 |
|---|---|---|
| 用户体验风险 | 延迟上升、页面崩溃、投诉增加、负反馈增加 | 是否有护栏指标和告警 |
| 交易风险 | 下单失败、支付失败、退款上升、履约异常 | 是否能小流量、可回滚 |
| 收入风险 | GMV、广告收入、转化率显著下降 | 允许最大损失是多少 |
| 合规风险 | 隐私、金融、医疗、安全等敏感场景 | 是否允许做对照实验 |
| 品牌风险 | 明显劣化体验、大范围舆情 | 是否需要白名单或灰度 |
| 工程风险 | 配置错误、参数下发失败、版本不兼容 | 是否有默认值和回退机制 |

可行性分析阶段就应该定义：

```text
如果护栏指标 X 在连续 N 个统计窗口内下降超过阈值，
或错误率 / 投诉率 / 延迟超过阈值，
则自动暂停实验或回滚到 control。
```


## 9. 快速 Checklist

- [ ] 业务问题是否具体到人群、场景、动作和指标？
- [ ] 预期收益是否明确，且值得占用流量和研发资源？
- [ ] 实验处理是否能被平台控制？
- [ ] 实验单元是否稳定，且与指标口径一致？
- [ ] 是否能随机分组并保持分组稳定？
- [ ] 用户之间、实验之间是否存在明显干扰？
- [ ] 目标人群和实验周期是否能支撑样本量？
- [ ] 曝光、行为、转化、护栏指标是否可观测？
- [ ] 是否有小流量、告警、回滚、止损机制？
- [ ] 如果不能做 AB，是否明确了替代评估方案？

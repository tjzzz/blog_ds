实验指标设计决定实验如何被解释和决策。指标必须在实验上线前定义，不能等结果出来后再挑对自己有利的指标。

一句话：**指标设计要回答“用什么判断成功、用什么解释变化、用什么保护底线”**。

## 1. 指标体系四层结构

| 指标类型 | 作用 | 示例 | 是否参与决策 |
|---|---|---|---|
| 核心指标 | 判断实验是否成功 | 支付转化率、次日留存、GMV、长点击率 | 强参与 |
| 辅助指标 | 解释核心指标为什么变化 | 点击率、加购率、停留时长、召回率 | 辅助参与 |
| 护栏指标 | 防止主指标提升但伤害体验或风险 | 投诉率、退款率、延迟、崩溃率、负反馈率 | 强参与 |
| 观测指标 | 发现潜在影响和异质性 | 分层人群、渠道、端版本、业务线表现 | 弱参与 |

核心原则：

- 核心指标不要太多，通常 1-2 个；
- 护栏指标必须提前定义；
- 辅助指标用于解释，不宜替代核心指标；
- 观测指标适合发现问题，但不能随意作为上线理由。

## 2. 指标口径必须写清楚

| 口径项 | 需要明确 |
|---|---|
| 指标名称 | 使用统一命名，避免同名不同义 |
| 业务含义 | 指标代表什么业务结果 |
| 分子 | 统计什么事件或金额 |
| 分母 | 以谁为基准：曝光用户、触发用户、全量用户、订单数 |
| 去重逻辑 | 按用户、设备、订单、请求还是内容去重 |
| 统计窗口 | 当天、7日、实验周期、转化窗口 |
| 归因窗口 | 曝光后多久内的转化算入实验 |
| 数据来源 | 曝光日志、行为日志、订单表、指标宽表 |
| 异常处理 | 黑产、内部用户、极端值、退款、取消订单如何处理 |
| 决策阈值 | 提升多少算业务显著，下降多少必须止损 |

## 3. 指标敏感性

[ab-test](ab-test.md) 中提到，实验检验的核心是看组间差异相对方差是否足够大：

$$
t = \frac{\bar Y_t-\bar Y_c}{\sqrt{Var(\bar Y_t-\bar Y_c)}}
$$

指标越稳定、方差越小，实验越容易检出真实效果。

具体的敏感性提升方法，例如增加样本量、长尾指标变换、CUPED、分层估计、前置指标、interleaving 等，单独放到 Experiment 难题中维护：

## 4. 搜索 / 推荐排序实验指标

[interleaving介绍](interleaving介绍.md) 中强调，排序实验中 AB 可能不够敏感，尤其是微小排序变化、低频 Query、Case 难复现时。

Interleaving 指标更关注单次请求中的偏好归因：

| 指标方向 | 说明 |
|---|---|
| 感知相关性 | 用户点击结果来自策略侧还是基线侧，结果位置是否更靠前 |
| 真实相关性 | 点击后停留、长点击、满意退出等真实满足程度 |
| 位置偏差校正 | A 优先和 B 优先要均匀抽样，抵消位置偏差 |
| 去重规则 | 相同 URL 或相同内容只能展示一次，归因规则要明确 |
| Case 分析 | 通过具体 query 和结果列表解释策略收益或损伤 |


## 5. 指标决策规则

| 结果组合 | 建议动作 |
|---|---|
| 核心指标显著正向，护栏无负向 | 扩量 / 全量 / 长期观察 |
| 核心指标正向但不显著 | 延长周期、扩大样本、检查方差，看业务价值 |
| 核心指标持平，护栏无异常 | 成本低可放弃；战略重要可重做实验 |
| 核心指标负向 | 暂停、回滚、定位原因 |
| 护栏指标负向 | 即使核心指标正向，也要谨慎上线或降级处理 |
| SRM / 数据异常 | 不做业务决策，先修数据或分流 |
| 分层结果冲突 | 检查辛普森悖论、样本偏差、异质性效果 |

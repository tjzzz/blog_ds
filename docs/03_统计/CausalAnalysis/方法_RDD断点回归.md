RDD 适用于 treatment 由某个连续分数或阈值规则决定的场景。

## 1. 适用场景

- 存在明确阈值，例如分数、等级、排名、额度、风险分；
- 阈值两侧个体非常接近；
- treatment 在阈值处发生跳变；
- 个体不能精确操纵自己落在阈值哪一侧。

## 2. 核心直觉

阈值附近的个体差异很小，可以近似认为 treatment 是随机分配的。

```text
刚好在线上的用户 vs 刚好在线下的用户
```

如果 outcome 在阈值处出现跳变，可以解释为 treatment 效果。


## 3. 简单例子

假设平台有一个用户成长激励规则：

```text
过去 7 天活跃分 >= 80 分的用户，会获得一张优惠券
过去 7 天活跃分 < 80 分的用户，不获得优惠券
```

现在想评估：发优惠券是否提升 7 日留存。

直接比较“拿到优惠券的人”和“没拿到优惠券的人”会有偏，因为高活跃用户本来就更容易留存。RDD 的思路是只看阈值附近的用户：

| 用户 | 活跃分 | 是否获得优惠券 T | 7日留存 Y |
|---|---:|---:|---:|
| A | 78 | 0 | 0 |
| B | 79 | 0 | 1 |
| C | 80 | 1 | 1 |
| D | 81 | 1 | 1 |

78、79 分和 80、81 分的用户很接近，可以近似认为他们除了“是否刚好拿到优惠券”之外，其他方面差异不大。

因此比较阈值 80 附近两侧的留存跳变：

```text
RDD 效果 ≈ 阈值右侧的留存 - 阈值左侧的留存
```

如果 80 分右侧的留存率明显高于 80 分左侧，并且其他协变量在阈值处没有跳变，就可以把这个跳变解释为优惠券的因果效果。

注意：RDD 估计的是阈值附近用户的局部效果，不一定能代表所有用户。

## 4. 基本步骤

1. 定义 running variable；
2. 确定阈值；
3. 选择阈值附近样本窗口；
4. 分别拟合阈值两侧趋势；
5. 估计阈值处 outcome 的跳变；
6. 做带宽、函数形式、操纵检验。

## 5. 诊断

| 检查 | 目的 |
|---|---|
| running variable 密度检验 | 判断是否有人为操纵阈值 |
| 协变量连续性检验 | 判断阈值两侧是否可比 |
| 带宽敏感性 | 看结果是否依赖窗口大小 |
| placebo cutoff | 换一个假阈值，看是否也有跳变 |


## 6. 阈值附近样本量太少怎么办

RDD 的优势是可信度较高，但代价是只使用阈值附近样本。如果边界附近样本太少，估计会非常不稳定。

可以考虑几种处理方式：

| 方法 | 做法 | 风险 |
|---|---|---|
| 适当扩大带宽 | 从 78-82 放宽到 75-85、70-90 | 离阈值越远，左右两侧越不像，近似随机假设变弱 |
| 延长观察周期 | 多积累几天或几周的阈值附近样本 | 规则和外部环境要保持稳定 |
| 换更高频指标 | 用次日留存、点击、完成率等中间指标辅助观察 | 中间指标不能完全替代最终指标 |
| 合并相似阈值或场景 | 多个国家、活动、门槛规则合并分析 | treatment 机制和指标口径要一致 |
| 改造成局部随机实验 | 在阈值附近随机发券/不发券 | 需要业务允许重新设计规则 |

带宽扩大时要做敏感性分析，例如分别看：

```text
75-85
70-90
65-95
```

如果结论只在某个带宽下成立，说明结果不够稳健。

如果样本量始终不足，不建议强行使用 RDD。可以考虑换方法：

| 情况 | 可考虑方法 |
|---|---|
| 有处理前后和对照组 | DID |
| 有多个类似业务单元 | 合成控制 / DID |
| 主要是可观测选择偏差 | PSM / Matching |
| 可以重新设计策略 | AB 实验 / 局部随机实验 |

## 7. 其他业务场景

- 信用分超过阈值获得权益；
- 风险分低于阈值进入审核；
- 活跃度达到门槛获得激励；
- 排名进入前 N 才获得曝光。

# 高阶实验难题_实验敏感性不足

实验敏感性不足，指的是：**实验真实存在效果，但因为样本量、指标方差、实验设计或指标选择问题，实验很难把这个效果稳定检出来**。

一句话：

> 实验敏感性解决的是：为什么业务上可能有用的策略，在实验结果里看起来“不显著”。

## 1. 先看公式：为什么会“不敏感”

在 AB 实验里，常见检验统计量可以直观理解为：

$$
t = \frac{\bar Y_t - \bar Y_c}{\sqrt{Var(\bar Y_t - \bar Y_c)}}
$$

如果两组样本量相同，可以近似写成：

$$
t = \frac{\bar Y_t - \bar Y_c}{\sqrt{\sigma_t^2/n + \sigma_c^2/n}}
$$

所以实验是否容易显著，取决于三件事：

| 因素 | 影响 |
|---|---|
| 组间差异 | 实验组和对照组差异越大，越容易显著 |
| 样本量 | 样本量越大，标准误越小，越容易显著 |
| 指标方差 | 指标方差越大，噪声越大，越不容易显著 |

提高实验敏感性，本质上就是：

```text
放大可检测的真实差异，或降低指标噪声。
```

## 2. 什么时候要怀疑敏感性不足

| 现象 | 可能原因 |
|---|---|
| 指标方向稳定正向，但一直不显著 | 样本量不足、方差太大、MDE 过小 |
| 分层里部分人群明显正向，整体不显著 | 人群异质性强，被整体平均稀释 |
| 小改动业务上合理，但 AB 完全看不出 | 指标不敏感，或者实验方式不适合 |
| 金额、时长类指标波动极大 | 长尾分布、极端值拉高方差 |
| 长期指标看不出，短期指标有变化 | 指标窗口太长、转化低频 |
| 搜索排序微调没有信号 | AB 对排序微调不敏感，可能需要 interleaving |

## 3. 提高实验敏感性的主要方法

| 方法 | 核心思路 | 适用场景 |
|---|---|---|
| 增加样本量 | 扩大流量或拉长实验周期，降低标准误 | 流量充足、实验风险可控 |
| 调整流量分配 | 两组尽量接近 50/50，提高统计效率 | 标准 AB，风险较低 |
| 降低指标方差 | 对长尾指标做截尾、winsorize、转换、分位数等处理 | GMV、时长、金额类长尾指标 |
| CUPED | 用实验前与目标指标相关的协变量做方差缩减 | 有稳定历史行为的数据 |
| 分层 / post-stratification | 按用户层级、端、地域等分层估计再加权 | 人群异质性强 |
| 更换前置指标 | 找更短周期、更敏感的代理指标 | 长期留存、复购、低频转化 |
| 聚焦触发用户 | 分析真正接触实验处理的人群 | 实验触发率低，但要注意触发偏差 |
| 换实验机制 | 对排序微调用 interleaving 等更敏感机制 | 搜索、推荐、排序实验 |
| 改实验设计 | 使用配对、区组、交叉等设计减少无关差异 | 可配对、可分层、自身对照场景 |

## 4. 方法一：增加样本量

这是最直接的方法。

可以通过：

- 提高实验流量；
- 拉长实验周期；
- 扩大目标人群；
- 减少不必要的排除规则；
- 合并多个低频场景。

但增加样本量不是万能的：

| 风险 | 说明 |
|---|---|
| 周期太长 | 外部环境、版本发布、节假日更容易干扰 |
| 流量太大 | 如果策略有风险，会扩大损失 |
| 人群扩大 | 可能引入不相关人群，稀释真实效果 |
| 机会成本 | 占用流量层，影响其他实验排期 |

## 5. 方法二：降低指标方差

很多业务指标天然长尾，例如 GMV、停留时长、订单金额、人均收入。少数极端用户可能让指标方差变得很大。

常见处理：

| 方法 | 说明 |
|---|---|
| 截尾 | 去掉极端高值或低值 |
| winsorize | 把极端值压到某个分位点，而不是直接删除 |
| log 转换 | 对强长尾金额类指标做对数变换 |
| 分位数指标 | 用中位数、P75、P90 替代均值 |
| 人群分层 | 对不同层分别估计，避免混在一起增大方差 |

注意：指标变换必须在实验前定义，不能实验后为了显著性临时换口径。

## 6. 方法三：CUPED 方差缩减

CUPED（Controlled Experiment Using Pre-Experiment Data）的核心思想是：

> 如果实验前的历史行为 X 和实验期目标指标 Y 高度相关，而且 X 不受实验影响，就可以用 X 来解释一部分 Y 的自然波动，从而降低方差。

定义调整后的指标：

$$
Y' = Y - \theta X
$$

如果 X 和 Y 的相关系数为 $\rho$，理想情况下有：

$$
Var(Y') = Var(Y)(1 - \rho^2)
$$

所以 X 和 Y 越相关，方差降低越明显。

例子：

| 实验指标 Y | 可用协变量 X |
|---|---|
| 实验期下单数 | 实验前一周下单数 |
| 实验期 GMV | 实验前一周 GMV |
| 实验期点击率 | 实验前历史点击率 |
| 实验期活跃天数 | 实验前活跃天数 |

使用 CUPED 的注意点：

- 协变量必须在实验开始前产生；
- 协变量不能受实验处理影响；
- 协变量和目标指标要有足够相关性；
- 新用户或无历史数据用户可能不适用。

## 7. 方法四：分层与 post-stratification

如果用户差异很大，把所有人混在一起会增加噪声。

可以先按重要维度分层：

- 新用户 / 老用户；
- 高活 / 中活 / 低活；
- iOS / Android；
- 城市等级；
- 商家等级；
- 流量来源。

然后在每层内估计实验效果，再按总体结构加权汇总。

这样做的好处：

- 降低人群结构差异带来的方差；
- 更容易发现异质性效果；
- 避免部分人群效果被整体平均稀释。

## 8. 方法五：选择更敏感的指标

有时候不是实验没效果，而是指标离实验动作太远。

例子：

| 实验动作 | 不够敏感的指标 | 更敏感的前置指标 |
|---|---|---|
| 搜索排序优化 | GMV | 长点击率、满意点击率、换 query 率 |
| 推荐卡片样式 | 次日留存 | 点击率、停留时长、负反馈率 |
| 下单页文案 | 复购率 | 提交订单率、支付转化率 |
| 新手引导 | 30 日留存 | 首日关键行为完成率 |

前置指标不能替代最终指标，但可以帮助判断机制是否生效。

## 9. 方法六：换实验机制

如果改动非常细，普通 AB 可能天然不敏感。

典型场景是搜索 / 推荐排序实验：

- 排序位置只发生微调；
- 低频 query 很难在实验组和对照组同时出现；
- 用户行为差异被 query 差异掩盖。

这时可以考虑 [interleaving](../ExperimentDesign/interleaving介绍.md)：让同一次请求中同时混排两个策略的结果，用点击和停留等行为判断用户更偏好哪一侧。

## 10. 不要为了敏感性牺牲可信度

提高敏感性时要避免几类错误：

| 错误做法 | 问题 |
|---|---|
| 实验后临时换指标 | 容易 p-hacking，增加假阳性 |
| 只看正向分层 | 多重检验问题，容易误判 |
| 只看触发用户 | 可能产生触发偏差，破坏随机性 |
| 任意剔除异常值 | 可能人为制造显著性 |
| 无限延长实验 | 容易受到时序干扰和外部冲击 |

原则：

> 敏感性提升必须在实验前设计，不能在实验后为了显著而改口径。

## 11. 快速 Checklist

- [ ] 当前实验的 MDE 是否符合业务真正关心的最小收益？
- [ ] 样本量是否足够？流量比例是否过于不均衡？
- [ ] 指标是否长尾？是否需要截尾、winsorize 或转换？
- [ ] 是否有实验前协变量可用于 CUPED？
- [ ] 人群异质性是否很强？是否需要分层？
- [ ] 当前核心指标是否离实验动作太远？是否需要前置指标？
- [ ] 当前实验机制是否适合该问题？排序类微调是否应该用 interleaving？
- [ ] 所有敏感性优化是否都在实验前定义？

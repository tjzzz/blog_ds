# 高阶实验难题：多重检验与显著性窥探

> 核心判断：指标看得越多、时间 peek 得越频繁，越容易把随机波动误判为显著。

## 1. 业务场景

常见情况：

- 实验看了几十个指标，只挑一个显著正向指标汇报；
- 每天看一次 p-value，哪天显著哪天停；
- 多个分层里只有某个小人群显著，就包装成实验成功；
- 多个实验组、多指标、多周期同时比较，没有做修正。

## 2. 为什么会错

如果每次检验都允许 5% 的第一类错误，检验次数越多，至少出现一次假阳性的概率越高。

```text
看 1 个指标：误报概率约 5%
看 20 个独立指标：至少 1 个误报的概率远高于 5%
```

频繁查看并提前停止实验，也会破坏原本的显著性解释。

## 3. 识别方法

- 实验报告是否事先定义了核心指标；
- 是否区分主指标、辅助指标、探索指标；
- 是否每天根据 p-value 决定停实验；
- 是否在大量分层中挑选显著结果；
- 是否进行了多重检验修正。

## 4. 处理策略

| 问题 | 处理 |
|---|---|
| 多指标 | 预注册核心指标；辅助指标只解释机制 |
| 多实验组 | 使用多重比较修正或控制 FDR |
| 多分层 | 分层结果作为探索，关键结论需要复验 |
| 频繁 peek | 设定固定实验周期，或使用序贯检验方法 |
| 中途停实验 | 记录停实验规则，避免人为挑时间点 |

常用修正：Bonferroni、Holm、Benjamini-Hochberg/FDR、序贯检验。

## 5. 平台化能力

- 创建实验时强制选择主指标；
- 报告区分「主分析」和「探索性分析」；
- 自动记录实验开始前的指标配置；
- 对多指标、多版本自动提示多重检验风险；
- 支持固定周期和序贯检验两种停止规则。

> 核心判断：只分析「触发了策略的人」或「留下来的人」，很容易把选择偏差当成实验效果。

## 1. 业务场景

触发偏差：

- 推荐策略只有部分用户触发，但只分析触发用户；
- 搜索排序策略只对有搜索行为的人生效；
- 优惠券策略只分析领券用户，而不是被分配到发券策略的人。

幸存者偏差：

- 只分析实验期间仍然活跃的用户；
- 只看完成订单用户的客单价，忽略流失/取消用户；
- 只看留存用户满意度，忽略已经流失的人。

## 2. 为什么会错

实验分组是随机的，但「触发」「留下」「完成」往往不是随机的。

如果实验策略本身影响触发概率或留存概率，只看触发/幸存样本，就会破坏随机性。

例子：

```text
B 组推荐更激进 → 更多低意向用户点击进入详情页
只分析详情页用户 → B 组样本质量变差
最后误判详情页转化率下降是详情页问题
```

## 3. 识别方法

- 对比 A/B 两组的触发率是否一致；
- 对比 A/B 两组的留存样本占比是否一致；
- 同时看「全量分配用户」和「触发用户」两套口径；
- 检查漏斗每一步是否被实验策略影响；
- 不要只在后验筛选出来的人群上做结论。

## 4. 处理策略

| 场景 | 建议口径 |
|---|---|
| 策略只影响部分人 | 同时报告 ITT 与 triggered analysis |
| 触发率被策略影响 | 以分配人群为主，触发人群只作机制解释 |
| 漏斗后段指标 | 同时看前段触发率和后段转化率 |
| 只看幸存用户 | 把流失、取消、未完成作为结果的一部分 |
| 人群筛选来自实验后行为 | 避免作为主分析口径 |

ITT（Intent-to-treat）口径：按最初被分配到实验的人分析，即使用户没有真正触发策略。

Triggered analysis：只看真正触发策略的人，但必须说明触发选择偏差风险。

## 5. 平台化能力

- 曝光日志区分「被分配」「被曝光」「被触发」；
- 报告自动展示分配人数、曝光人数、触发人数、完成转化人数；
- 漏斗每一步都展示 A/B 人数比例；
- 不允许只上传最终转化用户做实验分析。

# 高阶实验难题：辛普森悖论

> 核心判断：整体正向不代表所有人群正向；整体负向也可能掩盖关键人群收益。必须做分层检查。

## 1. 业务场景

辛普森悖论是指：整体数据呈现一个方向，但分组后每个子群体却呈现相反方向。

典型业务场景：

- 推荐策略整体点击率提升，但新老用户分别都下降；
- 活动策略整体转化率提升，其实是高意向用户占比变高；
- 搜索改版整体 GMV 提升，但核心类目下降，长尾类目上升拉高整体；
- 实验组更多命中了高活跃用户，导致整体效果被用户结构差异放大。

## 2. 本质原因

辛普森悖论通常不是「统计公式问题」，而是样本结构问题。

常见混杂变量：

- 用户分层：新用户/老用户、高活/低活、会员/非会员；
- 流量来源：自然流量、广告流量、push 流量；
- 端和版本：iOS、Android、Web，不同 app 版本；
- 时间：工作日/周末、活动期/平日；
- 商品/内容/类目：头部类目、长尾类目、不同价格带。

## 3. 识别方法

分析时至少做三层检查：

1. 整体效果：看总量指标；
2. 核心业务分层：新老用户、端、渠道、类目、地域；
3. 样本结构：实验组/对照组在各分层上的占比是否一致。

如果出现：

```text
整体：B > A
分层1：B < A
分层2：B < A
```

就需要怀疑辛普森悖论或样本结构偏差。

## 4. 处理策略

| 问题 | 处理 |
|---|---|
| 随机化失败导致结构不均 | 检查分流和 SRM，必要时重跑 |
| 样本结构自然波动 | 做分层分析、标准化加权、扩大样本 |
| 策略异质性明显 | 不做全量平均决策，按人群/场景定向上线 |
| 活动/渠道混入 | 拆分活动期和非活动期，或控制渠道变量 |
| 业务解释不清 | 回到机制：策略到底影响哪个人群、哪个链路 |

实验结论要避免只写「整体提升 X%」，而要写「在哪些人群提升，在哪些人群有风险」。

## 5. 平台化沉淀

实验分析系统应内置固定分层：

- 端：iOS / Android / Web；
- 用户：新老、高低活、会员等级；
- 渠道：自然、广告、push、搜索；
- 场景：核心入口、次级入口；
- 时间：日维度、周维度、活动期。

并在报告中自动提示：整体和分层方向是否冲突。

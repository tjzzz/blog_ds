> 核心判断：实验指标不是天然可信资产。口径变化、埋点变化、反作弊变化都会让实验结论失真。

## 1. 业务场景

常见情况：

- 实验期间埋点版本升级，A/B 两组覆盖端版本不同；
- 指标口径在实验中途调整；
- 反作弊策略变化导致点击率/转化率突变；
- 新策略改变用户行为路径，导致旧指标不再衡量同一件事；
- 实验组加载更慢，曝光埋点丢失，CTR 看似提升。

## 2. 高频原因

| 原因 | 例子 |
|---|---|
| 埋点口径变化 | 点击按钮从 click 改成 valid_click |
| 指标计算逻辑变化 | GMV 是否扣除退款，实验前后不一致 |
| 数据源变更 | 从客户端日志切到服务端日志 |
| 归因窗口变化 | 1 日转化改成 7 日转化 |
| 策略改变观测概率 | B 组曝光更多但日志丢失更多 |
| 反作弊规则变化 | 过滤掉大量异常点击，CTR 突降 |

## 3. 识别方法

- 查看实验期间是否有埋点、数仓、指标口径变更；
- 对比客户端、服务端、数仓多条链路；
- 看指标突变是否同时发生在多个实验；
- 检查曝光、点击、转化漏斗是否连续；
- 检查指标定义是否在实验前锁定。

## 4. 处理策略

| 场景 | 处理 |
|---|---|
| 指标中途改口径 | 按口径变更时间切段，或重算全周期 |
| 埋点漏报 | 先补数或剔除异常时间段，不直接决策 |
| 策略影响观测概率 | 使用服务端稳定指标或补充护栏指标 |
| 多链路不一致 | 以可信链路为准，并说明差异 |
| 指标不再代表目标 | 重新设计指标，必要时重跑实验 |

实验前要冻结主指标口径；实验后不能因为结果不好再换指标。

## 5. 平台化能力

- 指标元数据管理：分子、分母、过滤条件、窗口期；
- 指标版本管理：记录口径变更时间；
- 实验报告绑定指标版本；
- 埋点版本与实验版本联动；
- 指标异常自动告警和跨实验影响检查。

# Wiki 结构与维护规范

## 三层

1. **原始来源**：根目录 `Input/`，只读、默认不提交到公开仓库。`legacy_docs_2026-10-09/` 是旧博客 Markdown 的迁移快照，不等同于外部一手来源。
2. **对外 Wiki**：`docs/`。`topics/` 管领域问题，`entities/` 管单一概念，`relationships/` 管概念之间的机制与条件，`syntheses/` 管跨主题的决策总结。既有文章留在原路径，作为逐步编译的存量内容。
3. **结构约定**：本页定义字段、摄取、检查和发布规则。

## 页面字段

新页至少填写 `title`、`created`、`updated`、`tags`、`source`、`status`。`source` 存来源路径或公开 URL；从旧笔记提炼时，正文还要给读者可点开的旧文链接。`status` 用 `inventory`、`pilot`、`reviewed` 标明核查进度。

## 摄取

一次处理一个来源：读完整份资料 → 摘出可核实结论和疑点 → 更新对应主题/实体/关系/综合页 → 更新索引与[日志](wiki-log.md)。原始资料不直接改写。旧笔记若缺外部依据，只能作为**已有笔记**引用，不能把它包装成一手事实。

## 检查与发布

每次变更检查缺失来源、断链、重复概念、互相矛盾的说法和长期未更新页面。发布前检查待提交文件、敏感内容、MkDocs 构建及旧路径可用性。公开仓库中 `docs/` 外的已提交文件同样可被他人读取。

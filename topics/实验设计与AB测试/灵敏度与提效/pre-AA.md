# pre-AA：正式实验前的校准与检查

## 1. 什么是 pre-AA

pre-AA（pre-experiment A/A）是在正式 A/B 实验前，使用相同产品/策略版本构造两组“假处理组”，按拟用于正式实验的分流、埋点、指标计算和分析流程运行一次校准。两组实际上没有预期处理差异，因此其用途是检查流程和估计设计特征，而不是寻找产品效果。

有些组织会专门跑一场随机分组的 A/A；有些则利用历史数据、实验平台验证或持续的 A/A 流量。具体形式不同，核心在于：**用没有处理效应的场景检查实验系统是否按计划工作。**

pre-AA 位于正式实验之前，是一次端到端演练；它不能替代正式实验上线后的质量监控。正式实验开始后仍需按随机化单位检查实际分配比例（SRM），并在效果分析前确认异常已得到解释。SRM 的统计检测与诊断见 [SRM-分组样本比例不匹配](../分流与平台/SRM-分组样本比例不匹配.md)。

## 2. 它能帮助检查什么

| 目标 | 可检查内容 | 解释边界 |
| --- | --- | --- |
| 分流与数据链路 | 分组比例、曝光/埋点、样本进入分析的规则、指标聚合流程 | 发现异常后仍要定位根因，A/A 本身不自动证明是哪一环出错 |
| 分析校准 | 在零处理效应下，检验统计量、置信区间和分析流程是否异常 | 单次 A/A 偶然显著是可能的；应看流程与多次校准表现，不可把一次显著当作必然有 bug |
| 方差与样本量规划 | 估计指标噪声、组间差估计的标准误，为 MDE/样本量规划提供本地数据 | 历史窗口须代表正式实验的用户、周期和指标口径；方差估计有抽样误差 |
| 预处理/平台检查 | 检查随机化单位、数据完整性、样本成熟度及预设分析步骤能否执行 | 不能替代正式实验中的持续质量监控 |

若出现样本比例异常、埋点差异或意外的基线不平衡，应先排查随机化和数据链路；但**不能仅凭一场 A/A 的显著差异就断言一定是 SRM 或平台 bug**，因为在给定显著性水平下假阳性本来就可能发生。多次检查也要考虑重复检验和异常定位流程。

## 3. 它不能做什么

- **不能证明将来的 A/B 结果有效。** A/A 只能检验当前数据与流程在无处理差异条件下的行为，正式实验仍需检查实际分流、曝光和数据质量。
- **不能保证方差估计精确。** A/A 样本较少或实验周期不同，估计到的方差可能与正式实验不一致；应使用多个代表性窗口或历史样本，并记录不确定性。
- **不能自动决定 CUPED 系数或提升幅度。** CUPED 的协变量与估计方法应单独定义、评估，见 [CUPED](CUPED.md)。
- **不能代替预注册设计。** 指标、用户口径、实验周期、停止规则和异常处理不能在看完 A/A 或 A/B 结果后为追求显著而随意更换。

## 4. 建议的执行记录

每次校准至少记录：随机化单位与分流比例、实验/分析单位、指标口径与观察窗口、样本量和覆盖率、SRM/埋点/缺失检查、零效应下的效应估计与区间、方差估计来源、所用分析代码/版本、异常和处理结果。正式实验上线后继续按相同定义监控，不把 pre-AA 当作一次性“通行证”。

建议按以下顺序执行并留档：

```text
复用正式实验配置与数据链路
  → 检查分组与样本比例
  → 核对曝光/事件日志及指标计算
  → 运行预定分析脚本并记录异常
  → 修复问题后复测；标明尚未覆盖的链路
  → 正式实验启动后继续做 SRM 与数据质量监控
```

## 5. 与实验灵敏度和 CUPED 的关系

实验灵敏度不足时，可以通过增加有效样本量、改善指标、合适的方差缩减和实验设计来提升。pre-AA 的角色主要是**校准流程、检查数据质量并为规划提供经验信息**；CUPED 则利用处理前协变量降低效应估计方差。两者可以衔接，但解决的问题不同。

灵敏度总览见[灵敏度与提效总览](index.md)；CUPED 统一主笔记见 [CUPED](CUPED.md)；正式实验中的 SRM 检查见 [SRM-分组样本比例不匹配](../分流与平台/SRM-分组样本比例不匹配.md)。

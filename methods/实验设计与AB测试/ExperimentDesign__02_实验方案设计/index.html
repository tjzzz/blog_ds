    02_实验方案设计#

    实验方案设计的目标，是把已经通过可行性判断的业务问题，转成一份可以被研发、实验平台、数据分析和业务方共同执行的实验方案。

    它回答：实验要验证什么、对谁验证、采用哪种实验方式、跑多久、用多少流量、需要多少样本、什么结果算成功。

    0. 实验方案的核心结构#

    设计项 核心问题 关键产出
    实验假设 新策略预计让哪个指标发生什么变化？ 原假设、备择假设、成功标准
    目标人群 谁进入实验？谁不进入？ 人群圈选规则、排除规则
    实验单元 按什么对象随机？ user_id、device_id、merchant_id、order_id 等
    实验版本 对照组和实验组分别是什么体验？ control / treatment 说明
    实验周期 跑多久？是否需要预热、观察、归因窗口？ 开始时间、结束时间、观察窗口
    实验类型 用 AB、interleaving、区组、交叉、正交还是其他设计？ 实验方法选择
    实验流量 每组多少流量？是否分阶段放量？ 流量比例、放量计划
    最小样本量 能否检出业务上关心的最小效果？ 样本量、MDE、功效约束
    并行约束 是否与其他实验互斥、正交或依赖？ 流量层和互斥关系

    实验方案可以按三块来写：

    1. 实验基本设定：实验假设、目标人群、实验单元、实验版本、实验周期。
    2. 实验类型选择：根据业务问题选择 AB、Interleaving、区组、交叉、正交等实验方式。
    3. 实验流量设计：流量比例、放量节奏、样本量、MDE 和并行约束。

    1. 实验基本设定#

    实验基本设定要先把“业务想法”翻译成“可执行实验”。这一部分不解决统计细节，而是先明确：要验证什么、对谁验证、怎么处理、跑多久。

    1.1 实验假设#

    实验假设不是“看看有没有效果”，而是可检验的因果陈述。

    如果我们对目标人群上线某个策略 / 功能 / 模型，
那么核心指标会相对对照组提升至少 X，
并且护栏指标不会显著变差。

    一个完整的实验假设通常包括 5 个元素：

    元素 说明 示例
    实验对象 对谁生效 新用户、搜索用户、活跃商家、某城市用户
    干预动作 改了什么 新排序模型、新补贴策略、新页面文案、新推荐卡片
    核心指标 判断成功的主指标 支付转化率、长点击率、次日留存、GMV
    最小收益 业务上值得上线的最小变化 +0.5pp、相对提升 2%、GMV +1%
    风险约束 哪些指标不能变坏 投诉率、退款率、延迟、崩溃率、负反馈率

    1.1.1 原假设和备择假设#

    实验分析里的假设可以写成：

    假设 含义 示例
    原假设 H0 实验组相对对照组没有提升，或者提升不够业务阈值 新策略不会提升支付转化率
    备择假设 H1 实验组相对对照组存在提升，且达到业务关注方向 新策略会提升支付转化率

    业务上更推荐把假设写得更具体：

    H0：新策略对支付转化率没有正向影响。
H1：新策略使支付转化率相对提升至少 2%，且退款率不显著上升。

    1.1.2 成功标准#

    成功标准要同时包含统计标准和业务标准：

    标准 说明
    统计显著 指标差异不是随机波动导致，例如 p-value < 0.05 或置信区间不跨 0
    业务显著 提升幅度足够值得上线，例如收益覆盖研发成本、流量成本和风险成本
    护栏不坏 投诉率、退款率、延迟、崩溃率等关键风险指标不能显著变差
    分层稳定 关键人群、端、地域、渠道没有明显负向

    1.2 实验目标人群#

    目标人群要同时满足两个条件：业务上 relevant，统计上可比。

    规则类型 需要明确什么 示例
    准入规则 谁可以进入实验 登录用户、新用户、搜索场景、指定城市、指定端版本
    排除规则 谁不能进入实验 内部员工、机器人、黑产用户、异常账户、已参加冲突实验用户
    触发规则 用户满足什么行为后才真正进入统计 进入搜索结果页、进入支付页、推荐流实际曝光
    分层规则 哪些维度后续需要分层观察 新老用户、端、地域、活跃度、流量来源、商家等级

    注意：

    • 不要让实验组和对照组使用不同的人群过滤逻辑，否则会破坏随机性。
    • 如果实验只在触发后才生效，分析时要区分“分桶用户”和“实际触发用户”。
    • 排除规则必须在实验前确定，不能实验后为了结果好看再剔除人群。

    1.3 实验单元#

    实验单元指“按照什么对象随机分组”。它必须和业务干预、指标口径、随机分桶保持一致。

    实验单元 适用场景 风险
    user_id 用户体验、转化、留存实验 未登录用户覆盖不足
    device_id / cookie_id 未登录场景 清缓存、换设备会跳组
    merchant_id / shop_id 商家策略、B 端实验 商家之间可能竞争或互相影响
    item_id / content_id 内容、商品策略实验 用户会看到多个内容，容易交叉污染
    order_id 履约、订单策略 同一用户多订单体验不一致
    query / request_id 搜索请求级实验 用户体验不稳定，不适合长期体验实验

    选择原则：

    • 用户体验类实验，优先按用户分。
    • 商家权益类实验，优先按商家分。
    • 搜索排序类局部实验，可以考虑 query / request 级，但要注意体验一致性。
    • 实验单元和指标单位不一致时，要提前定义聚合方式。

    1.4 实验版本#

    实验版本要讲清楚 control 和 treatment 分别是什么，不要只写“新版”和“旧版”。

    版本 需要说明
    Control 当前线上默认策略 / 页面 / 模型 / 参数是什么
    Treatment 改了什么，改动范围多大，参数如何配置
    多实验组 每个实验组之间的差异是什么，是否能互相比较
    默认回退 实验异常时回退到哪个版本

    建议写法：

    Control：线上现有搜索排序模型 v1。
Treatment A：上线排序模型 v2，调整相关性特征权重。
Treatment B：上线排序模型 v2 + 新摘要策略。

    1.5 实验周期#

    实验周期不是随便定几天，而要覆盖足够的业务波动和转化窗口。

    时间概念 说明
    预热期 策略刚上线时，避免缓存、学习、冷启动等影响
    实验运行期 用户持续进入实验分组并接受处理
    观察窗口 指标统计覆盖的时间范围
    归因窗口 曝光后多久内的点击、转化、支付算入实验
    数据回收期 停止新流量后，等待后续转化完成

    确定周期时要考虑：

    • 是否覆盖完整周内周期，例如工作日和周末；
    • 是否避开大促、节假日、版本发布、投放活动；
    • 目标指标是否低频或延迟，例如复购、留存、退款；
    • 样本量是否能在周期内达到要求。

    2. 实验类型选择#

    实验类型选择的核心是：根据业务问题、随机化条件、指标敏感性和风险成本，选择最合适的验证方式。

    整合 实验方式、ab-test、interleaving介绍，常见实验设计方式如下。

    类型 适合场景 设计要点
    完全随机设计 / AB Test 单一策略、功能、文案、流程改动 将样本随机分到 control 和 treatment
    配对设计 两个对象天然可配对，或同一对象前后可比 控制个体差异，提高敏感性
    随机区组设计 不同地域、端、用户层级差异明显 先分层，再在层内随机
    交叉设计 / Interleaving 同一用户 / 请求可同时比较多个策略，常见于搜索排序 更敏感，但指标设计复杂
    析因设计 多个因素可能同时影响结果 估计主效应和交互效应
    正交设计 因素组合太多，不能全量组合实验 选取代表性组合，降低实验成本
    拉丁方设计 多个因素水平数相同，且交互较弱 控制行、列等多个干扰因素

    2.1 AB Test#

    AB Test 适合大多数线上产品实验。基本思想：随机抽取两份或多份流量，一部分看到旧版，一部分看到新版，通过指标差异判断效果。

    关键前提：

    • 分组随机且稳定；
    • 两组只在实验处理上不同；
    • 样本量足够；
    • 指标口径上线前定义；
    • 先校验 SRM 和数据质量，再看显著性。

    适合：

    • 页面改版；
    • 文案、按钮、流程优化；
    • 推荐策略、补贴策略、触达策略；
    • 大多数可控线上功能实验。

    2.2 Interleaving#

    Interleaving 适合搜索、推荐、排序类微小改动。它让用户在一次请求中同时看到两个策略混排后的结果，再根据点击、停留等行为判断哪一侧更优。

    适合它的原因：

    • 对排序微调更敏感；
    • 所需流量更小；
    • 低频 Query 也能在同一次请求中比较；
    • 更容易抽取 case 分析。

    但它不适合所有实验，因为指标归因、展现去重、位置偏差处理都更复杂。

    2.3 随机区组 / 分层实验#

    当人群差异很大时，可以先分层，再在层内随机。

    适合：

    • 城市差异大；
    • 新老用户差异大；
    • iOS / Android 行为差异大；
    • 不同商家等级差异大。

    好处是减少组间噪声，提高实验敏感性；坏处是设计和分析更复杂。

    2.4 析因 / 正交实验#

    当多个因素同时变化时，单独做 AB 可能效率很低。

    例如同时想测试：

    • 标题文案 A/B；
    • 按钮颜色 A/B；
    • 推荐卡片样式 A/B。

    如果全组合就是析因设计；如果组合太多，可以用正交设计挑选部分代表性组合。

    3. 实验流量#

    实验流量设计要回答：给多少流量、怎么分配、怎么放量、需要多少样本、能检出多小的效果。

    3.1 流量比例#

    常见流量分配方式：

    分配方式 适用场景 示例
    50/50 标准 AB，追求最高统计效率 control 50%，treatment 50%
    90/10 高风险新策略，小流量验证安全 control 90%，treatment 10%
    多实验组均分 多个 treatment 同时比较 control 25%，A/B/C 各 25%
    不均衡分配 新策略风险高或资源成本高 control 80%，treatment 20%
    分阶段放量 先验证安全，再验证效果 1% → 5% → 20% → 50%

    一般来说，在总样本量固定时，50/50 的两组实验统计效率最高；但在高风险场景下，不一定一开始就追求最高效率，要先控制风险。

    3.2 放量节奏#

    推荐把实验流量拆成几个阶段：

    阶段 流量比例 主要目的
    空转 / A/A 不改变策略 验证分流、埋点、指标链路
    **冒烟**验证 0.5% - 1% 验证配置、参数、日志、错误率
    小流量 5% 左右 观察护栏指标和明显负向
    中流量 10% - 20% 初步观察核心指标方向和分层表现
    大流量 50% 左右 积累样本，做正式统计判断
    全量 100% 上线后监控，必要时保留 holdout

    3.3 样本量计算#

    样本量回答的是：为了检出业务关心的最小效果，需要多少用户 / 请求 / 商家 / 订单进入实验。

    样本量受几个因素影响：

    因素 对样本量的影响
    基线转化率 / 指标均值 基线越低，通常越难检出小幅变化
    MDE 希望检出的效果越小，需要样本越大
    指标方差 方差越大，需要样本越大
    显著性水平 α α 越严格，需要样本越大
    统计功效 power power 越高，需要样本越大
    分组比例 越偏离 50/50，通常需要更多总样本

    对于均值类指标，AB 实验常看统计量：

    t = \frac{\bar Y_t-\bar Y_c}{\sqrt{Var(\bar Y_t-\bar Y_c)}}

    如果两组样本量相同，可以近似写成：

    t = \frac{\bar Y_t-\bar Y_c}{\sqrt{\sigma_t^2/n + \sigma_c^2/n}}

    直觉上：

    • 组间差异越大，越容易显著；
    • 样本量越大，标准误越小，越容易显著；
    • 指标方差越大，越不容易显著。

    3.4 MDE#

    MDE（Minimum Detectable Effect）是最小可检测效果，表示在给定样本量、显著性水平和统计功效下，实验能稳定检出的最小指标变化。

    它回答：

    这次实验不是能不能发现任何变化，
而是能不能发现业务真正关心的最小变化。

    比如当前 CTR 基线是 10%，实验组真实提升到 10.1%。如果当前实验设计的 MDE 是 0.5 个百分点，那么 10% → 10.1% 这个 0.1 个百分点的提升就很难被稳定检出来；这不是说它一定没效果，而是当前样本量和指标波动不足以证明它。

    逻辑推导#

    MDE 本质上是从样本量公式反推出来的：

    给定样本量 n、显著性水平 α、统计功效 power，
反推这次实验最小能稳定检出的差异 δ。
这个 δ 就是 MDE。

    以转化率、点击率、留存率这类比例指标为例。

    对照组转化率：p_c
实验组转化率：p_t
真实提升：δ = p_t - p_c
每组样本量：n

    我们关心的是两组比例差：

    \hat{\delta} = \hat{p}_t - \hat{p}_c

    当两组样本量相同，且实验组和对照组的基线接近时，可以用基线转化率 p 近似两组方差：

    Var(\hat{p}_t - \hat{p}_c) = Var(\hat{p}_t) + Var(\hat{p}_c) \approx \frac{p(1-p)}{n} + \frac{p(1-p)}{n} = \frac{2p(1-p)}{n}

    所以两组差异的标准误是：

    SE = \sqrt{\frac{2p(1-p)}{n}}

    如果使用双侧检验，显著性水平为 \alpha，统计功效为 power，那么要让一个真实差异 \delta 被稳定检出，需要满足近似条件：

    \delta \ge (Z_{1-\alpha/2} + Z_{power}) \times SE

    因此比例指标的 MDE 近似为：

    MDE = (Z_{1-\alpha/2} + Z_{power}) \times \sqrt{\frac{2p(1-p)}{n}}

    常用设定是：

    α = 0.05，双侧检验，所以 Z_{1-α/2} ≈ 1.96
power = 0.8，所以 Z_power ≈ 0.84
1.96 + 0.84 ≈ 2.8

    所以常用简化公式是：

    MDE \approx 2.8 \times \sqrt{\frac{2p(1-p)}{n}}

    均值类指标的 MDE#

    如果指标是人均 GMV、人均停留时长、订单金额这类均值指标，思路类似，只是把比例方差换成指标方差。

    设指标标准差为 \sigma，每组样本量为 n，两组样本量相同，则：

    SE = \sqrt{\frac{2\sigma^2}{n}}

    均值类指标的 MDE 近似为：

    MDE = (Z_{1-\alpha/2} + Z_{power}) \times \sqrt{\frac{2\sigma^2}{n}}

    在 \alpha = 0.05、power = 0.8 时：

    MDE \approx 2.8 \times \sigma \times \sqrt{\frac{2}{n}}

    因此均值类指标里，标准差 \sigma 越大，MDE 越大，实验越不敏感。这也是为什么 GMV、金额、时长这类长尾指标经常需要做截尾、winsorize、CUPED 或分层。

    3.5 实验敏感性不足怎么办#

    如果样本量够但实验仍然难以检出效果，通常是实验敏感性问题，例如指标方差太大、人群异质性强、指标离实验动作太远，或实验机制不适合当前问题。

    这部分作为高阶实验难题单独维护，见：☆如何提升实验灵敏度。

    3.6 并行实验约束#

    实验流量不是无限资源。方案设计阶段就要说明当前实验和其他实验的关系。

    关系 含义 示例
    互斥 两个实验不能同时命中同一用户 两个搜索排序模型实验
    正交 两个实验可以同时命中，但分流相互独立 搜索排序实验 + UI 样式实验
    依赖 一个实验必须在另一个实验基础上运行 新策略包内的子实验
    隔离 高风险实验独占某层或某类人群 支付链路、核心交易链路实验

    如果两个实验会同时影响同一个核心指标，或者归因不清，优先互斥；如果只是弱相关，可以正交，但分析时要检查交互影响。

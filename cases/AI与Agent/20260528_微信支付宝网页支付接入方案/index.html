    微信/支付宝网页支付接入方案#

    调研时间：2026-05-28
    场景：PC 电脑网页 + 手机网页，自有 Flask Web App，已注册个体工商户

    一、场景与支付方式选择#

    用户访问设备/环境 微信支付方式 支付宝方式
    微信内网页（公众号/H5） JSAPI 支付 手机网站支付（WAP）
    手机端浏览器 H5 支付 手机网站支付（WAP）
    PC 电脑网页 Native 支付（扫码） 电脑网站支付
    iOS App App 支付 App 支付

    你的项目 aigc-humanizer-en（Flask Web App）最可能用到：
    - PC 端 → 微信 Native 扫码 + 支付宝电脑网站支付
    - 手机端 → 微信 H5 支付 + 支付宝手机网站支付

    二、前置条件#

    微信支付#

    条件 要求
    主体 企业营业执照或个体工商户
    额外账号 微信**服务号**（订阅号不支持微信支付）
    域名 已备案域名
    实名认证 企业/个体户三证合一
    API 配置 API v3 密钥 + API 证书
    JSAPI 额外 商户平台配置 JSAPI 支付授权目录
    入驻难度 ⭐⭐⭐ 较严格

    支付宝#

    条件 要求
    主体 **企业或个体工商户**即可
    额外账号 只需支付宝账号
    域名 配置授权域名（需 HTTPS）
    密钥 生成 RSA2/SHA256 密钥对，上传公钥
    回调 配置异步通知地址（Notify URL，公网可访问 HTTPS）
    合规 根据经营类目提交营业执照、ICP 备案、特定行业资质
    入驻难度 ⭐⭐ 相对宽松

    结论#

    有个体工商户执照即可接入两者。支付宝门槛更低，不需要额外注册服务号。

    三、开发流程#

    3.1 微信支付 JSAPI（公众号内网页）#

    用户访问网页
  → 后端 OAuth 获取 openid
    → 后端调 JSAPI 下单接口 → 获取 prepay_id
      → 前端 WeixinJSBridge 调起微信支付
        → 用户确认支付
          → 微信异步通知 + 前端回调
            → 后端查单确认 → 完成

    核心 API 接口：

    接口 说明
    POST /v3/pay/transactions/jsapi 下单，获取 prepay_id
    GET /v3/pay/transactions/id/{id} 查询订单
    POST /v3/pay/transactions/close 关闭未支付订单
    支付成功回调通知 异步推送，需验签
    POST /v3/refund/domestic/refunds 退款
    下载交易账单 对账用

    关键参数：
    - openid：用户唯一标识（必须）
    - prepay_id：有效期 2 小时，过期需重新下单
    - time_expire：可选，不传默认订单有效期 7 天
    - 前端下单按钮必须做**防抖处理**

    官方文档： https://pay.weixin.qq.com/wiki/doc/apiv3/open/pay/chapter2_3.shtml

    3.2 支付宝电脑网站支付#

    用户点击支付
  → 后端构造订单参数 + RSA2 签名
    → 返回 form 表单 / 跳转链接
      → 自动跳转支付宝收银台
        → 用户扫码或登录支付
          → 同步返回 (return_url) + 异步通知 (notify_url)
            → 后端验签 → 更新订单 → 完成

    核心 API 接口：

    接口 方法标识 用途
    下单支付 alipay.trade.page.pay 发起支付，生成跳转
    查询订单 alipay.trade.query 查询支付状态
    退款 alipay.trade.refund 全额或部分退款
    撤销订单 alipay.trade.cancel 撤销未支付订单
    对账单下载 alipay.data.bill.download.query 下载对账文件

    官方文档： https://opendocs.alipay.com/open/270/105899

    四、费率对比#

    支付方式 标准费率 备注
    微信支付（JSAPI/H5/App） 0.6% 部分行业可申请 0.38%
    支付宝（网站/App/WAP） 0.6% 部分行业可申请 0.38%
    微信扫码支付（Native） 0.38% 线下扫码场景
    退款 免费 双方均免费
    • 单笔最低手续费 0.1 元
    • 结算周期：默认 T+1 自动结算到绑定银行卡
    • 无接口调用费、无年费

    五、Python 技术实现#

    5.1 Python SDK#

    平台 SDK 安装命令
    微信支付 v3 wechatpayv3 pip install wechatpayv3
    支付宝 alipay-sdk-python pip install alipay-sdk-python

    5.2 推荐架构（Flask 项目）#

    用户点击支付 → Flask 后端创建订单（DB 记录 pending）
  → 用户选择「微信」或「支付宝」
    → 分别调用对应 SDK 接口
      → 监听各自的异步回调通知（独立路由）
        → 验签 → 统一更新订单状态为 paid
          → 自动开通服务

    代码组织建议：

    payment/
├── __init__.py
├── base.py          # 抽象支付接口
├── wechat.py        # 微信支付适配器
├── alipay.py        # 支付宝适配器
└── models.py        # 订单模型

    利用适配器模式，统一两种支付的调用和回调处理逻辑。

    5.3 关键安全要点#

    • 异步通知必须验签：微信支付 v3 用证书验签，支付宝用 RSA2 公钥验签
    • 异步通知才是业务依据：同步返回（前端跳转）仅用于用户体验，不能作为订单完成的依据
    • 金额用分（整数）传输：避免浮点精度问题
    • 回调 URL 必须是 HTTPS：两者都要求
    • 防止重复回调：同一订单号可能收到多次通知，需幂等处理

    六、接入策略建议#

    维度 建议
    先接哪个 支付宝（门槛低、不需要服务号、开发更简单）
    最小闭环 先接支付宝电脑网站支付（PC+手机通用），1-2 天跑通
    完整方案 支付宝网站支付 + 微信 JSAPI + Native，覆盖全场景
    开发周期 单个平台 1-2 天；双平台 3-5 天（含测试联调）
    测试 微信有沙箱环境；支付宝有开发测试模式

    七、个人收款码 vs 官方接口的本质区别#

    个人收款码 官方支付接口
    做法 放一张图片 API 对接
    回调通知 ❌ 无 ✅ 异步通知
    自动对账 ❌ 手动核对 ✅ 自动完成
    并发订单 ❌ 易混乱 ✅ 天然支持
    适合场景 偶尔收钱、订单极少 自动化业务

    即使有个体户执照，也建议走官方接口而非收款码。官方接口的核心优势是**自动化**——支付成功自动回调、自动更新订单状态、自动开通服务。

    实验分析方法全景图谱（ab-exp 梳理）#

    主线：一个实验从「想验证点子」到「拍板」是一条生命周期流水线；所有进阶技术要么解决某一环节问题，要么都在回应同一个核心矛盾——既想随时看结果、又想别把噪声当显著（假阳性失控）。

    0. 五大阶段生命周期（位置总览）#

    阶段 核心问题 涉及方法
    1. 设计 不做会错哪？ 假设 H0/H1、主/次/守护指标、MDE、power、样本量
    2. 预实验 系统可信吗？基线多大？ pre-AA（A/A 校验 + 估真实方差）、CUPED 协变量准备
    3. 运行分流 流量怎么分？ 固定 50/50（传统）/ MAB（自适应）/ CSR 客户分群路由
    4. 分析推断 谁更好？可信吗？ p 值（频率派）/ 贝叶斯胜率 / 序贯分析
    5. 决策 全量？迭代？下线？ 胜率、期望提升、guardrail 越界回滚

    1. 核心矛盾：peeking → 假阳性膨胀#

    频率派固定样本检验假定「样本量预先定、只在点一次性看结论」。但人忍不住中途偷看（peek），每看一次等于做一次检验 → 名义 α=5% 会随查看次数累积膨胀（每周看、跑半年，实际假阳性率可冲到 30%+）。所有「进阶方法」都从这儿长出来。

    2. 三条出路#

    2.1 序贯分析（Sequential Analysis）—— 频率派内部修正#

    • 本质：承认你会一直看，用 math 把 α 摊到整个时间序列，保证**任意时刻**假阳性率 ≤ α。
    • 工具箱：成组序贯检验、alpha-spending functions（O'Brien-Fleming / Pocock）、always-valid p-value（始终有效 p 值）。
    • always-valid CI（置信序列，Confidence Sequence）：序贯下「任意时刻都有效的置信区间」的数学对象。传统 CI 只在固定 n 有效；置信序列是一串随样本量收窄、但在每个时点都成立的区间（Howard et al. 2018 体系）。它与 always-valid p 一体两面：能推出 always-valid p，也能推出 always-valid CI。这是「允许你随时停」的形式化保证。
    • ⚠️ 命名澄清：本图谱中缩写 CSR 不指「置信序列」，而指 Customer Segmentation Routing（客户分群路由），属于分流模式，见 §3.3——与序贯/推断无关。
    • 一句话：传统检验「到点一次性宣判」；序贯分析「随时可查、全程控错」。

    2.2 贝叶斯胜率（Bayesian Winning Rate / P(B>A)）—— 换一套世界观#

    • 传统 p 值回答「假设没差异，看到这么极端数据的概率」——不直接说「哪个更好 / 好多少概率」。
    • 贝叶斯：给每个变体后验分布（先验+数据），直接算 P(B>A)=赢的概率，以及期望提升、可信区间（credible interval）。
    • 天然顺序有效：后验随时更新，今天看明天看都合法，没有「一次性宣判」前提 → 不存在 peeking 问题。
    • 沟通直观：「B 比 A 好的概率 95%、期望提升 3%」比「p=0.03」好懂。
    • 但它不是银弹：① 结果依赖先验（选错会偏）；② 「胜率 95%」易被误读成「长期有 95% 把握赢」，其实只是当前数据后验信度；③ 频率派质疑它不保证长期错误率。正确姿态：贝叶斯胜率是**决策沟通利器**，控错常仍靠频率派序贯（很多平台后端用序贯频率派，前端给你看贝叶斯胜率汇报）。

    2.3 MAB（Multi-Armed Bandit）—— 改分流、不改推断#

    • 关键区别：序贯分析 / 贝叶斯解决「推断有效性」；MAB 解决「流量分配效率」。
    • 传统 A/B 50/50 固定，哪怕第 2 天发现 B 明显差，仍硬塞一半流量给 B（浪费）。
    • MAB 自适应：按实时表现动态调权重，把更多流量给赢家（探索-利用权衡）。常见：Epsilon-greedy、UCB、Thompson Sampling（贝叶斯 MAB——拿后验当采样分布选臂）。
    • 代价：推断变复杂（不再简单随机对照），需上下文（contextual bandit）；「边跑边倾流量」使后期组间可比性受损，事后因果解读要小心。
    • 适用：流量稀缺、短期转化优化、探索价值低；**不适合**需干净因果归因或长期 holdout 验证的场景。

    3. 贯穿工具与分流模式#

    3.1 CUPED（Controlled-experiment Using Pre-Experiment Data）#

    • 位置：分析阶段（第 4 阶段），与 p 值/贝叶斯并列，不替代它们，而是**让它们更快更省**。
    • 原理：用实验**前**协变量（如用户实验前活跃度）构造控制变量，压低指标方差，均值估计不变（无偏）。方差变小 → 同 MDE 下样本量更小 / 同样本量下更早显著。
    • 进阶：CUPAC（用 ML 预测值当协变量）。
    • 与 peeking 关系：不解决 peeking，但让你更快到达「该看结论」的点，间接减少偷看冲动。可与序贯、贝叶斯叠加。

    3.2 pre-AA（预实验 A/A）#

    • 位置：第 2 阶段（预实验），正式跑之前。
    • 两种含义：① 实时 A/A（两组给相同处理）验证分流随机、采集无误、无 SRM（样本比失衡）；② 用历史数据估**真实方差基线**，喂给样本量计算（不让样本量拍脑袋）和 CUPED 协变量选择。
    • 价值：很多「实验翻车」其实是系统本身有偏（SRM）。pre-AA 是防火墙。

    3.3 CSR：客户分群路由（Customer Segmentation Routing）#

    • 位置：第 3 阶段（运行分流），与「随机 50/50 / MAB」并列的一种**分流模式**。
    • 是什么：按用户分群维度（地域、设备、新老客、行为标签等）把流量**路由**到指定变体/处理——即「哪类人看哪个版本」由规则/分群配置决定，而非纯随机或纯自适应学习。
    • 与其他分流的区别：
    • vs 固定 50/50：后者无差别随机；CSR 是**分群定向**，常用于「某类用户先上某功能」「按市场灰度」。
    • vs MAB：MAB 靠数据**自动**把流量倾给赢家；CSR 是**人工/规则**驱动的分群路由，不学习、不优化短期收益。
    • 典型用途：定向实验（只对某客群验证）、灰度/按群发布、避免对敏感客群误伤、与 MAB/随机并行时做「分群 override」。
    • 注意：CSR 是**分流机制**，不解决 peeking/假阳性，也不影响推断有效性本身；它回答「流量怎么按人分」，而非「结果可不可信」。

    4. 组合拳（真实成熟平台的样子）#

    1. pre-AA 校验系统 + 估方差基线
    2. 用基线 + CUPED 协变量 → 算样本量、准备方差缩减
    3. 运行期：用**序贯分析**（always-valid）做 peeking 防护；或上 MAB 做流量自适应
    4. 分析期：CUPED 缩减方差 + **贝叶斯胜率**做决策汇报（后端仍由序贯频率派控错）
    5. 决策：胜率 + 期望提升 + guardrail 越界回滚

    5. 决策对照表：卡在哪儿用哪个#

    你卡在… 该用
    不确定实验系统本身准不准 pre-AA（A/A test）
    样本量怎么定 / 要跑多久 设计阶段 power/MDE（用 pre-AA 估的真实方差）
    想随时看又怕假阳性 序贯分析（alpha-spending / always-valid）
    想跟老板说「赢的概率多大」 贝叶斯胜率 P(B>A) 做汇报
    流量贵、想少浪费在差变体 MAB（Thompson Sampling）
    指标噪声大、收敛慢 CUPED / CUPAC 方差缩减

    6. 常见坑#

    • 贝叶斯胜率 ≠ 免死金牌：解决沟通/决策直观，但不自动解决「拿胜率当停稿线反复 peek 提前停」的选择偏差。严谨平台用 always-valid 框架兜住。
    • MAB 与干净因果冲突：要长期价值验证用 Holdout，不要全量 MAB。
    • SRM 优先于一切：先看样本比是否失衡，失衡则整轮结果不可信。
    • 虚荣指标当北极星：主指标必须单一且不被游戏化。

    7. 一句话串联#

    设计(power) → 预实验(pre-AA 校准+估方差) → 运行(固定50/50 / MAB / CSR分群路由) → 推断(p值 / 贝叶斯胜率 / 序贯) → 决策(胜率 / 回滚)。
    CUPED 与 pre-AA 是前后两端的「提效+校准」锚点；序贯分析 / 贝叶斯胜率 / MAB 是「随时看 vs 控错」矛盾的三种解法。

    8. 补充模块与技术（本图谱之外的关键拼图）#

    8.1 实验形态（设计层）#

    • 析因/多变量测试（Factorial / MVT）：一次测多因子，估主效应+交互
    • 重叠/分层实验（Overlapping / Layered / Orthogonal buckets）：多实验同时跑互不污染（Google 常态）
    • 灰度/渐进发布（Canary / Progressive Delivery）：feature flag + 实验一体，解耦部署与发布
    • 地理实验（Geo experiment）：按地域随机，解决跨用户溢出
    • 群集/图聚类随机（Cluster / Graph-cluster randomization）：处理网络干扰

    8.2 因果与干扰（核心前沿缺口）#

    • 网络效应 / 干扰（Interference / SUTVA 违反）：社交/双边市场下溢出污染
    • 溢出建模（spillover / beta-gamma 建模）
    • 准实验补充：DID、断点回归、PSM（随机不可行时）
    • 触发/依从分析（Trigger / Complier analysis）：只分析真正触达用户

    8.3 异质效应与个性化（大热点）#

    • HTE / CATE（异质/条件平均处理效应）
    • Uplift 建模：区分 Persuadables / Sure Things / Sleeping Dogs / Lost Causes
    • 因果森林（Causal Forest, honest splitting）、S/T-Learner
    • 个性化实验 → Targeting policy；Qini / AUUC 评估

    8.4 长期价值与代理指标#

    • 短期 vs 长期指标冲突
    • Holdout（客留组）长期价值测量
    • 代理/替代指标（Proxy / Surrogate，如 PACE）：用短期代理预测长期
    • 领先指标（leading indicators）

    8.5 方差缩减进阶（CUPED 之外）#

    • CUPAC（ML 预测值当协变量）
    • 分层 CUPED / 后分层（post-stratification）
    • 触发方差缩减（trigger-based variance reduction）

    8.6 治理与质量闸门#

    • SRM（样本比失衡）自动监控（比 pre-AA 更日常的防火墙）
    • 多重比较校正（multiple comparison correction）
    • 新奇效应（novelty）/ 首因效应（primacy）
    • 实验库 / 知识沉淀（避免重复实验、AI 重跑 loser）

    8.7 自动化与 AI 原生实验#

    • Auto-Experimentation：自动样本量、自动诊断、自动 peeking 防护
    • AI 生成假设/变体（Prompt-Based Experimentation）
    • 实验 Agent（自动读结果/写报告）
    • LLM 用于实验分析与异常诊断

    8.8 隐私与基础设施#

    • 隐私保护实验（privacy-preserving）
    • 第三方 cookie 退场 → first-party data + 联邦学习 / on-device
    • Warehouse-native：结果在 Snowflake/BigQuery/Databricks 算，与财务对齐
    • 服务端实验（server-side）替代客户端

    8.9 实验缝合（组合创意 · 单层互斥 · 快速寻优）⭐前沿监控项#

    • 定义（镇哥场景）：广告创意等场景，多个素材排列组合成不同变体，且素材间**相互影响（交互效应）** → 整组排列组合必须落在**同一互斥层（mutually-exclusive layer）**，不能用正交分层（否则同一用户会同时看到多个组合的素材，结论被污染）。
    • 与重叠实验的关系：Google OI 把系统参数分到不同 layer，跨层正交、层内互斥；GrowthBook 用 namespaces 做互斥。缝合 = "层内互斥"的极端形态——所有排列组合共享一个互斥层（GrowthBook blog, 2026-10-01 原文：experiments inside a layer stay mutually exclusive；Google partitions system parameters into layers… experiments inside a layer stay mutually exclusive）。
    • 核心矛盾（镇哥原问）：组合爆炸 → 每层流量被 N 个组合平分 → 单组合统计 power 暴跌、找最优组合极慢。博客原文点明代价：Exclusion costs power, so use it sparingly（互斥牺牲 power、制造排队）。
    • 解法前沿（监控方向）：
    • 因子/部分因子设计（Factorial / Fractional Factorial）：一次测多因子，估主效应+交互；组合爆炸时用**部分因子 / 正交表（Orthogonal Array）**降维，以最少组合覆盖主效应+低阶交互。
    • 组合多臂老虎机（Combinatorial Bandit / Thompson Sampling over combinations）：边跑边把流量倾给优组合，序贯寻优（与 §2.3 MAB 一脉，但臂=组合空间）。
    • 最优组合识别（Best-arm / Top-K identification）：序贯找最优/Top-K 组合。
    • 交互效应监控（缝合的 SRM 平替）：Google 在层内跑 daily job 检查"每对重叠实验的组合效应 ≠ 各自效应之和"；GrowthBook 同款用 **SRM 检验 + multiple-exposure 预警 + 健康度检查**兜底未预测冲突（博客原文：A daily job checks every overlapping pair of experiments for combined effects that depart from the sum of the pair's separate effects）。
    • 信源：GrowthBook《run multiple experiments trustworthy results》(2026-10-01，含 Google layers / namespaces / SRM / interaction check 原文)；Kohavi《Trustworthy Online Controlled Experiments》；DoorDash(12k 实验/年)、Microsoft(hundreds daily)、Meta(~20k concurrent) 工程博客；创意组合实验（Meta/Google Ads creative combination testing）；arXiv bandits / causal inference。
    • 一句话：缝合 = 把"相互影响的排列组合"关进同一互斥层跑，靠因子/正交表降维 + 组合 bandit 序贯寻优 + 层内交互效应 daily check 来又快又可信地找出最优组合。
    • 深度方案：见 方案调研-并发实验可信架构与缝合落地.md（GrowthBook 博客原理深挖 + 缝合落地方案：架构/分配/监控/统计/运维 + 对比表）。

    9. 业界方向 2025–2026（公开前沿检索）#

    1. AI 原生实验：LLM 生成假设/变体、实验 Agent 自动读结果（Optimizely Opal、Kameleoon Prompt-Based、Adobe Journey Optimizer Agent）；约束从「生产变体」转向「流量/优先级/记忆」。OpenAI 收购 Statsig = 用实验评估 prompt/模型/AI 特征。
    2. AI 产品自己的实验：测试 prompt、模型、AI 特征（Datadog LLM Experiments、LaunchDarkly AI Experiments/Versioning）；实验平台成 AI 安全发布一环。

    2026-09-28 AI变现机会简报（周一例行）#

    执行：radar（组织外部感知器） ｜ 窗口：9/25–9/28（不足处扩至 9/18–9/28，逐条标日期）
    核验方式：GitHub 17 个跟踪仓库 + 3 组检索 API 全部实时拉取；其余为联网检索，置信度逐条标注
    ⚠️ 本文件只给「值得人看 / 观察 / 忽略」初筛，不做四问终审、不立项、不决策

    今日判断#

    世界怎么变：两条线同时加速——① 「去 AI 味」这件事本身被彻底商品化：14 天内 GitHub 新建 humanizer 相关仓库 1,329 个，中文区「去AI味」新建 113 个，且已长出「路由器层」（de-ai-router 把 10 个 skill 串成一个入口）与「SEO 引流层」（同账号批量做 awesome/alternatives 列表 repo，全部带 UTM 溯源）——方法不再是壁垒，入口和分发才是；② 中国高校 AIGC 检测制度化在本期被第二次确认，9/18–9/24 再添 5 所一手通知（南昌航空、湖北大学 MBA、哈工程、山东大学、海南科技职业大学），阈值集中在 ≤30% / ≤35% / ≤40%，平台**全部是知网 / 维普 / 格子达**。

    对镇哥意味着什么：Huma 的差异化假设「过双检=解决客户卡点」第二次出现裂缝——大陆学位论文的实际卡点在知网/维普，不在 Turnitin + aidetector 矩阵内；同时，Huma 的对手不再只是别的 humanizer 产品，而是「一千多个免费 skill + 一个路由入口」这种零边际成本供给。反过来，本期拿到一条**本期最重要的有利证据**：The Atlantic 9/25 长文引述 Notre Dame CS 团队论文——"可靠的检测器可以被 humanizer 工具骗过"首次进入学术与主流媒体口径，等于人类化有效性被第三方背书。建议动作：不再加注"通过率承诺"，把资源转向"客户实际卡点"的取证与分发入口。

    机会清单（11 条）#

    1. paperclip — 开源「零人类公司」编排台冲上 GitHub Trending 榜首#

    • 来源：GitHub（repo ） ｜ 来源类型：GitHub Trending + 第三方追踪
    • 时间：2026-09-27 日榜第 1（GitHub API 核验日 9/28：push=2026-09-28）
    • 总结：把「多 agent 当公司管」做成开源产品——组织架构图、心跳、目标对齐、工单、硬预算上限、审批闸门、持久 agent 状态、原子任务检出、可审计活动流；BYO agent（OpenClaw / Claude Code / Codex / Cursor / Bash / HTTP）。
    • 事实：89,929★ / fork 15,668 / MIT / TS / 单容器自托管 / 219 contributors / 周级发版（GitHub API 实时核验）；官网 paperclip.ing 为文档站，无付费版；第三方追踪记「月度 +9k★、bus factor 2、top-author share 37%」（repositoryradar ，中置信）。
    • 推断：「编排器 + 审批闸门 + 预算」这一层已被 87k★ 级 MIT 项目免费化，且是**自托管**（说明它的对手不是 SaaS，是没有人再为这一层付钱）。
    • 适合谁做：不适合包装（见 GitHub 节打分）。
    • 难度/投入：自托管中（Node 20+/pnpm/内嵌 Postgres，npx paperclipai onboard --yes 一键）。
    • 可验证信号：GitHub API 星级/fork/贡献者/发版频率；PH 无对应条目。
    • 关联业务线：组织 / 探索线（AgentTeam 模板包）
    • 初筛结论：值得人看（不是作为包装机会，而是作为**探索1 差异化假设的直接反证**）

    3. Univer — 「Agent 的 Office 运行时」#

    • 来源：GitHub（repo ） ｜ 类型：GitHub Trending + 周榜
    • 时间：9/27 push（9/22–9/26 周榜在列）
    • 总结：把表格 / 文档 / 幻灯片 / Canvas / 关系表 / PDF 合成**一个运行时**，供 agent 程序化编辑 + 输出验证。
    • 事实：20,237★ / Apache-2.0 / TS（API 核验）；第三方周报明确「协作者、导入导出、图表、透视为**商业授权 Pro** 功能」（tommyz ，中置信）。
    • 推断：agent 要产出"可交付文件"这件事正在被标准化；这对**内容线（图文/封面/文档产出）**与**Huma（交付物形态）**都是基础设施级变化。
    • 适合谁做：有前端能力 + 有具体交付场景的人（不是通用机会）。
    • 难度/投入：高。
    • 可验证信号：GitHub API；商业 Pro 授权页。
    • 关联业务线：内容 / Huma（交付物形态）
    • 初筛结论：观察

    4. TrustMRR 全库底数首次拿到：11,240 个项目，90.4% 月验证收入 < $1,000#

    • 来源：crawlora 对 TrustMRR 的快照 （2026-09-20） ｜ 类型：收入验证聚合
    • 时间：快照 2026-09-20，随查（检索日 9/28）
    • 总结：独立开发者/SaaS 的支付商验证收入分布。
    • 事实：11,240 个公开项目；**仅 9.6% 过 1,000 MRR**；10K–50K 仅 1.9%、$250K+ 仅 8 个（最高 $3.6M，Stan）；21.2% 正在挂牌出售；Stripe 占支付通道 56.8%；AI 是最大的单一大类目（89.5% 带 top-category 标签）。

    10. 推断（对 Huma 最重要）："人类化能骗过检测器"这件事第一次同时被学术论文 + 主流媒体确认 → Huma 的技术路线有了第三方背书；但**背书是公共品，不是 Huma 的独占**。真正的稀缺在"Turnitin 不公开、不可试错"这一条——这是 Huma 手里唯一对手抄不动的资产。
